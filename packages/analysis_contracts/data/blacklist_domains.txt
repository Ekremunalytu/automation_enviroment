# Matching is host-suffix aware: a blacklisted "evil.example" also matches any
# subdomain (e.g. "c2.evil.example") but NOT a different registrable domain
# ("notevil.example", "evil.example.org"). Both the static rule
# (static_runtime.rules.s4_blacklisted_domain, scans extension source/manifest)
# and the dynamic rule (packages.analysis_engine.rules.a7_blacklisted_domain,
# checks observed outbound hosts) read this single curated copy.
#
# ── SAFETY: this file is INERT — the hosts are NEVER contacted ────────────────
# The loader (packages.analysis_contracts.domain_indicators) only READS this file
# and STRING-MATCHES the entries against scanned source / observed-traffic hosts.
# There is NO resolver, NO DNS lookup, and NO HTTP fetch anywhere that reads it,
# so listing a real malicious host here cannot make the dev environment reach it.
# Real C2/relay IOCs are intentionally listed UN-DEFANGED because they must be
# exact match targets — but they are pure data, never a fetch instruction. The one
# toolchain step that does make live requests, markdown-link-check, is configured
# (.mlc_config.json ignorePatterns) to SKIP every real IOC host, and a guard test
# (tests/security/test_ioc_safety.py) pins both properties so they cannot regress.
#
# The seed entries below use RFC 2606 / RFC 6761 reserved TLDs (.example /
# .test / .invalid) so the shipped default is a SAFE, clearly-synthetic
# placeholder set. Operators replace these with their own threat-intel feed
